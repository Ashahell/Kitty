# AGENTS.md — Kitty: Core Awakening

A design/planning folder for *Kitty: Core Awakening*, an AROS-only 3D puzzle-platformer to be built LLM-first. This local folder is **not a git repo** and has no code or build config — just the GDD. The upstream project repo is https://github.com/Ashahell/Kitty (verified as of 2026-10: 1 commit, only `README.md` + MIT `LICENSE`, no code yet). Treat the GDD as the spec until real code exists; once code exists, code beats this file and the GDD.

## Source of truth

- `Docs/Development/kitty_core_awakening_design.md` — the consolidated game design document. Read it before any design decision; it answers story, mechanics, licensing, engine, and milestone questions.

## Facts an agent will get wrong if not told

- **Platform target is AROS only**, on the team's in-progress Vulkan port. But develop and CI-test on **Linux Vulkan first**; AROS cross-compile only after a headless Vulkan smoke test passes.
- **Engine is a small custom C++20 engine** (~10–20k lines). Explicitly NOT a port of Godot/Bevy/Fyrox/O3DE. Deps per GDD §8: Vulkan (+ volk/Vulkan-Hpp, deferred until AROS WSI settles), SDL2 (AROS port), glm, meshoptimizer, Dear ImGui, miniaudio (+ libopenmpt for .mod), glslangValidator as a non-negotiable CI shader check.
- **Isolate WSI (`VK_KHR_surface`)** behind one interface so the rest of the engine stays portable and testable on Linux.
- **Fork/Join (clone replay) is the riskiest subsystem.** Build it at M2 with determinism guarantees — fixed timestep, seeded RNG, replay validation — before anything grows around it.
- **Licensing is a hard architectural constraint:** Kitty and AROS are trademarks; all official art/names/assets must be swappable placeholders ("skins") from day one. ReBoot references stay texture-level homage only. Community content requires a license field (CC-BY / CC-BY-SA / GPL-3.0-or-later) enforced at the manifest schema level.

## Milestone workflow (from GDD §11 — the operating rules)

- One milestone per session (M0 triangle-on-Vulkan → M7 contrib pipeline), each with automated acceptance tests.
- Everything must strict-compile / type-check before a milestone counts; commit after every milestone.
- Moveset is frozen until M3; arcade launches with 3 disks, not 10.
- Gate scope: fork/join and Intuition-windows ship in the story; BOOPSI subclassing and playground may slip to post-launch.

## Git / upstream

- Upstream: https://github.com/Ashahell/Kitty — public, MIT-licensed, effectively empty (README + LICENSE). Don't assume any code or history exists there; don't search GitHub for "Kitty" code to build on.
- The local folder is not yet wired to it. If starting code work, init/clone the upstream repo rather than inventing a new layout; the GDD's "commit after every milestone" rule refers to upstream commits.
- Top-level MIT license covers the engine layer; the GDD gates game assets separately (trademarks/skins rule above) — don't blanket-license art.

## Repo layout

- `Docs/Development/` — the GDD lives here. New design docs belong here too.
- Game code, when it starts, is expected to be a C++20 engine + game built around the M0→M7 milestone ladder. Keep new top-level directories minimal and purposeful; don't scaffold code until a milestone calls for it.
