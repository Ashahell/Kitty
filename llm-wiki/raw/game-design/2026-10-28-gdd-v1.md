# Kitty: Core Awakening — Consolidated Game Design Document

*An AROS-themed 3D puzzle-platformer with playground/Sims elements, built for AROS on Vulkan, developed LLM-first.*

---

## 1. Project Overview

**Title:** *Kitty: Core Awakening*
**Post-story mode:** *Kitty's Workbench Life*
**Protagonist:** Kitty — the anthropomorphic cat mascot of AROS (created by Eric Schwartz)
**Genre:** 3D puzzle-platformer → persistent playground with Sims elements
**Platform:** AROS only, on the team's in-progress Vulkan port
**Development:** Fully LLM-driven, milestone-based, machine-verifiable acceptance criteria
**Target:** The Amiga/AROS community first; crossover appeal via cozy-Sims and puzzle-platformer audiences

**Design thesis:** The story *teaches* the operating system (fork/join, windows, classes), the world *celebrates* the culture (Fred Fish disks, READMEs, binomes), and the playground gives it somewhere to live forever — built, like AROS itself, by many hands.

- **Kitty and the AROS name are trademarks.** The original Kitty artwork is by Eric Schwartz. Permission from the AROS team is required before release.
- **Architecture requirement:** all Kitty art, names, and AROS-specific assets must be swappable placeholders from day one. Treat official assets as a licensed "skin."
- **ReBoot elements** remain texture-level homage only: binomes, descending Game Cubes, "Game Over — User Wins" phrasing. No character names, designs, or the "ReBoot" name itself.

- **Community content** requires a license field (CC-BY / CC-BY-SA / GPL-3.0-or-later) enforced at the manifest level.
- **Moderation:** a report/revocation pipeline for community content must exist before launch (checksum revocation — "the Archivist can exile a disk from the Library").

## 3. Story — The SMP Arc

### 3.1 Premise

In AROS-land, the Kernel has always run on a **single Core**. The citizens — daemon programs — queued at the Scheduler, one task at a time. Then the **Great Panic**: a rogue process called **Deadlock** consumed the Core, froze the Scheduler, and hung the System permanently.

Kitty — the long-dormant **init process**, first of all processes — wakes from swap space. Beneath AROS-land lie **dormant Cores**, each holding a fragment of multi-core knowledge. Kitty must awaken them all.

### 3.2 Act structure — the chronology of Kickstart

Each chapter is named for a Kickstart version; art direction follows the era:

| Chapter | Era | Look |
|---|---|---|
| 1 | Kickstart 1.0 | The Dawn — sparse, near-monochrome, hardware beeps |
| 2 | Kickstart 1.3 | The golden age — full Workbench palette, sampled audio |
| 3 | Kickstart 2.0 | The gray upheaval — flat gray-blue; resistance-to-change as theme |
| 4 | Kickstart 3.1 | Maturity — richest art; the Cores awaken |

**The reason the Cores are dormant:** the Kickstart ROM itself was corrupted. Each awakened Core returns a module's true self. The ending is a **warm reboot** — the System rises with all modules resident and all Cores online, and everything the player saved stays saved.

### 3.3 The Kickstart modules as characters

- **Exec** — the Scheduler: overworked, single-threaded, exhausted; his collapse is the inciting incident
- **Intuition** — the Blind Oracle: arranges all Screens and Windows; cannot see herself, sees everything through everything else
- **Graphics** — the vain painter, hoarding blitter time
- **DOS** — the archivist-librarian; colleague of Fred Fish
- **Layers** — the quiet one who keeps the world from tearing when Windows overlap; players meet him exactly once

### 3.4 The five Cores

| Core | Theme | Power granted |
|---|---|---|
| 68k Core (the Ancestor) | warm nostalgia; Amiga 500 aesthetic | Basic movement; story begins "in the time of one" |
| PPC Core | fractured mirror-world; the lost path | **FORK** — split into a thread-clone |
| x86 Core | industrial; coolant pipes; enormous scale | **JOIN** — merge with a clone, keeping position/cargo |
| ARM Core | low-power garden; minimal, quiet | **MUTEX** — lock gates/bridges for clones |
| SMP Core (the Heart) | convergence of all cores | **SEMAPHORE** — sequence multiple clones |

**Final battle:** Deadlock holds all locks and waits forever. Kitty wins by forking herself across every awakened Core at once — true SMP, many Kitties in parallel — overwhelming the wait cycle. The Scheduler sings. Credits roll over a visibly faster Workbench.

### 3.5 The closing beat

The final battle is not won by Kitty's forks alone: **the Contribs arrive** — every module and gadget the player collected, arriving as other people's work. The moral lands without a speech: *no single process saves an operating system.*

## 4. Core Mechanics

### 4.1 Base moveset (frozen until story ships)

| Action | Input | Intent |
|---|---|---|
| Run/jump | standard | baseline |
| "Cat on keyboard" — lie on a node to pause/resume platforms and patrols | hold crouch on node | signature mechanic: freeze time by sitting on things |
| Pounce — short-range dash-strike, breaks corrupted blocks | double-tap direction | combat-lite; mostly a puzzle tool |
| Defrag — rearrange one screen's tiles once per checkpoint | contextual | the brain-bender |
| Nine Lives — death rewinds 9 seconds as a "saved state" | passive | diegetic checkpointing |

### 4.2 Fork/Join — SMP as gameplay

- **FORK:** spawn a clone replaying your *recorded actions* in real time — a physical second Kitty on a second Core
- **JOIN:** merge with a clone; keep its position and cargo. Two Kitties push a block neither could push alone; one holds a switch while the other passes
- **MUTEX:** a clone locks a bridge — but only one Kitty holds a lock at a time; deadlock puzzles teach *why deadlock is bad*, hands-on
- **SEMAPHORE:** order clones' actions; sequence switches rhythmically

Reference points: *The Talos Principle* recording puzzles crossed with *Baba Is You* rule manipulation, wrapped in cat. Players learn real concurrency concepts by accident.

**Technical warning:** this is the riskiest system in the game and the most likely place LLMs produce subtle bugs. Build it at **M2** with determinism guarantees: fixed timestep, seeded RNG, replay validation — before the rest of the game grows around it.

### 4.3 Intuition's gift — window management as 3D puzzle verbs

- **Windows are physical objects** Kitty grabs and drags
- **Depth arrangement:** a window sent to back becomes ghostly (pass-through); brought to front, solid. Cross a chasm by dragging a window into it, ghosting it, walking through, re-fronting it as a floor
- **Screens as places:** public vs. custom screens; drag a window from one Screen to another to change its properties (an ice window in the Fire Screen melts into ridable water)
- **Requester gates:** literal System Requesters block paths — `[Retry]` restarts the room's puzzle; `[Cancel]` dismisses the obstacle *and closes something behind you*. Every door is a dialog with the OS; Cancel is always tempting, always costly

### 4.4 BOOPSI — the Library of Lineage

BOOPSI (Basic Object Oriented Programming System for Intuition) is a temple where every object knows its class, and every class its superclass, back to `rootclass`.

- **Kitty can subclass herself:** at BOOPSI shrines, declare `Kitty extends Feline` and *inherit* powers from what she extends — found abilities are class definitions
- **Chapter mystery:** an orphan object that doesn't know its superclass, glitching in and out of existence. Recovering its lineage (a fetch-quest through old header files) lets it instantiate — it joins the playground as a resident
- **Multiple inheritance** exists as forbidden, unstable, *extremely tempting* magic — one late-game shrine allows it; results are chaotic and wonderful

## 5. The ReBoot Layer (homage texture)

- **Binomes** — citizens are 1-binomes and 0-binomes (walking numerals). A binome couple producing a child is a small arithmetic event the street celebrates
- **Game Cubes** — glowing cubes periodically descend on Workbench districts, sealing them in energy domes. Kitty enters and plays a mini-game. **Win:** rewards, dome lifts. **Lose:** "GAME OVER — USER WINS" — district binomes are **nullified** (grayed, half-erased) until restored from backup. This is the fail-state economy
- **Old READMEs** — scattered `.readme` files: lore, jokes, corrupted ones needing repair, hints written *in-universe by earlier guardians* — some by **a previous Kitty**
- **The Archivist** — Phong homage (not a copy): serene, robed keeper of the Great Archives; "**Alpha-numeric!**"; settles disputes with games of chance he is suspiciously good at; speaks in README quotations
- **The User** — never seen, always felt; the sky flickers with their presence; oldest citizens speak of them in lowercase reverence

## 6. Fred Fish & The Arcade

**Fred Fish** exists in-world as the legendary, near-mythical wanderer who sailed the floppy seas distributing over a thousand **Public Domain disks**. Missing since the Great Panic.

**Fred Fish disks are the collectible** — styled as labeled floppies ("FF #437"), hidden in every level. **Each disk contains one mini-game:** collecting disks *is* collecting the arcade. Winning cubes feeds the playground economy (cycles, bytes, hardware-trinket furniture), closing the loop.

| Disk | Mini-game | Homage |

| FF #001 | Bouncing Ball | Amiga Boing demo (physics toy; tutorial cube) |
| FF #023 | Marble Mayhem | Marble Madness — isometric ball-roller |

| FF #234 | Critters | Lemmings — marching binomes with assignable jobs |
| FF #337 | Bricklayer | Arkanoid — paddle/ball, power-up pills |
| FF #412 | Turbo Lotus | Lotus-style pseudo-3D road racer |

| FF #999 | The Fish Itself | Secret fishing mini-game; Fred Fish is on the dock. He's always been there |

## 7. Post-Story Playground — *Kitty's Workbench Life*

Once the SMP Core awakens, the game continues as a persistent neighborhood:

- **Daemon Sims:** rescued programs become residents with routines, moods, and System-themed needs: **cycles** (energy), **memory** (food/fullness), **I/O** (social), **uptime** (fun). Neglect → sluggish, grumpy, eventually swapped to disk
- **Build mode:** construct from motherboard parts — RAM-stick benches, capacitor planters, ribbon-cable roads. Zoning: residential / commercial (swap markets) / parks (coolant gardens)
- **Economy:** cycles and bytes, earned via Scheduler-posted jobs (mini-game variants of story mechanics: "fork four clones to sort this data stream")
- **SMP fantasy:** a busy neighborhood visibly runs on your awakened cores — more residents, more parallel life on screen
- **Stretch goal:** other players' Kitties visit over the network — leave gifts; fork a helper clone that stays 24 hours of uptime

**Design rule:** the build editor ships day one, free, in the box — it *is* the contribution editor (see §9).

## 8. Engine & Technical Stack

**Recommendation: a small custom C++20 engine** — not a port of Godot/Bevy/Fyrox/O3DE.

Rationale:
1. The hardest subsystem (Vulkan WSI on AROS) is *already the team's work* — combining it with the existing SDL2 AROS port gives a platform layer in weeks, not years
2. Porting Godot to AROS is a second massive project that would consume all effort
3. LLMs excel on a small, well-defined codebase (~10–20k lines, clean API) rather than patching a million-line engine
4. Everything is text and checkable; C++ has the most verifiable LLM workflow that exists

```
C++20
├── Vulkan (team's AROS port; develop/CI on Linux Vulkan first)
├── volk + Vulkan-Hpp      — loader/bindings (defer until AROS WSI settles)
├── SDL2 (AROS port)       — window, input, audio
├── glm                    — math
├── meshoptimizer          — pipeline sanity
├── Dear ImGui             — dev/debug UI
├── miniaudio              — sound (plus libopenmpt/custom player for .mod)
└── glslangValidator       — shader CI check (non-negotiable)
```

**Workflow rules:**
- Shaders compile-checked and pipelines validated in CI on Linux *first*; every milestone includes a headless Vulkan smoke test before any AROS cross-compile
- `VK_KHR_surface`/WSI is the known unknown — isolate it behind one interface so the 95% of the engine that isn't WSI stays portable and testable
- Vulkan failure modes are unforgiving (validation layers, pipeline layouts, descriptor mismatches); never let an LLM refactor working code without tests

### Art & audio direction

- Low-poly stylized, two-register look: 68k Core flat-shaded retro → later cores fuller lighting — the engine visibly evolves with the story
- Workbench blue/orange palette; Guru Meditation easter eggs ("Cat Meditation" on death); a level titled "Bouncing Ball"
- Kitty: low-poly, expressive, squash-and-stretch, verlet-chain tail physics
- **Soundtrack as real MOD files** (ProTracker, four-channel samples) via libopenmpt or custom player; dynamic music mutes/unmutes channels contextually — an authentic 1989 trick that still works
- **Joystick-first controls:** digital joystick, one button + directions; everything else is enhancement

## 9. The Contributions Mechanic — The Contribs

*AROS's actual source tree has a Contribs directory where community ports and tools live. The game borrows the real culture.*

### In-fiction

The **Contribs** are a guild — wandering artisans, tinkerers, port-maintainers. When Deadlock crashed the Kernel, the Contribs kept patching, kept submitting, kept the tree alive. Fred Fish is their patron saint; the Archivist keeps their registry.

### The contribution loop

1. **Build** — players create in playground build mode: rooms, daemon NPCs, furniture, mini-game levels, whole Fish disks
2. **Package** — wrapped as a Fred Fish disk with a manifest: title, author, version, license, dependencies, content hash. Installable by dropping into the game's `Contrib/` drawer
3. **Validate** — the game "compiles" it: schema check, resource limits, content policy, license field present. Failures produce a **Guru Meditation with the specific line** — the classic error screen as your build log
4. **Publish** — locally instantly; optionally to the community repository
5. **Integrate** — accepted disks appear in-world: new arcade cabinets, furniture catalogs, daemon residents, new Game Cubes

### Review culture

- Submissions enter a **"Pending" mailbox** at the Public Domain Library
- Other players test-run pending disks in a **sandboxed Game Cube** before voting
- Approval is themed as a **commit**: revision stamp + handle appended to the **AUTHORS file** — a real, in-game scroll of every contributor, open-source style
- Reputation = commit count, shown as **stripes on Kitty's scarf** — cosmetic, irresistible

### Content package format

```
Contrib/
  FF-1042_marble_mayhem_levels/
    manifest.json      # schema-validated: name, author, version, license, deps
    content/           # levels, sprites, .mod files
    scripts/           # AREXX-style glue, sandboxed
    checksum.sig
```

- **All text, all schema'd** — machine-checkable community content, same philosophy as milestone acceptance tests
- **Hard sandbox:** scripts run restricted — no filesystem access outside their drawer; CPU/memory caps themed as Sims resources
- **Datatypes pipeline:** new object types register as datatypes; the core game never needs patches to accept new content — the AROS way
- **Versioning:** disks show `v1.3 (34.4)` style strings; multiple versions coexist gracefully
- **No license field → no compile.** CC-BY / CC-BY-SA / GPL-3.0-or-later only

### Contribution types

| Type | In-game home | Effort |
|---|---|---|
| Playground lots & decorations | Furniture catalogs, street layouts | Low (in-game editor) |
| Daemon NPCs | Recruitment office | Low (personality sliders + routines) |
| Game Cube levels | Fish Arcade cabinets | Medium (per-mini-game level editor) |
| Whole mini-games | New Fish disks | High (documented mini-game API) |
| .mod soundtracks | Playground jukebox/radio | Low |
| Translations | Locale drawer | Low |
| Story content | READMEs, questlines via quest API | Medium |

**Rules:** editor ships day one, free; single-player never depends on the network (sneakernet file-sharing works — the Fred Fish way); moderation/revocation pipeline before launch.

## 10. Additional Systems & Flavor

- **The Shell as fast travel:** hidden/earned CLI console — `cd /dev/Disks`, `loadwb`, `assign` jokes; real AROS commands teleport Kitty; an easter-egg mine that teaches actual commands
- **Saves as a visible filesystem:** the "rescue disk" — real directory structure, visible, backable-up, tradeable. *Kitty saves herself to DF0:*
- **AREXX macros:** late-game power — record-and-replay your own fork/joint solutions; recordings are shareable files (demoscene catnip); doubles as a replay/demo mode
- **WHDLoad-style level-pack format** for DLC/community content — one wink that signals "we know exactly who this is for"
- **ENVARC as settings:** the options menu is ENV:/ENVARC: — graphics settings are environment variables
- **Benchmark mode:** "SYS: benchmark" timed runs with demo-style camera — speedrunning leaderboard for the demoscene-adjacent crowd
- **The Second Kitty arc:** the READMEs from "a previous Kitty" pay off — an earlier init process still resident, swapped to disk at the edge of the System. Optional questline, bittersweet ending, sequel hook
- **Localization from day one:** DE/FR/IT/SV — Amiga's heartland was Europe; small cost, disproportionate goodwill
- **Demo disk marketing:** playable demo packaged as a .adf image "fitting on one floppy" — retro press coverage for free
- **Open-source strategy:** engine layer open (useful to AROS itself, recruits contributors, de-risks IP); assets gated until licensing clears
- **M6 champagne rule:** the engine's job system should itself be SMP-parallel — drink your own champagne

## 11. Milestones (LLM-Driven)

1. **M0:** Triangle on AROS via the team's Vulkan port — validates everything else
2. **M1:** Kitty model, camera, terrain, input — one 68k Core test room
3. **M2:** FORK/JOIN — clone recording; determinism tests (fixed timestep, seeded RNG, replay validation)
4. **M3:** One full Core (68k) with puzzles
5. **M4:** Remaining Cores; Deadlock boss
6. **M5:** Playground mode — daemon needs, build tools, save-as-filesystem
7. **M6:** Performance pass — SMP-parallel job system
8. **M7:** Contrib pipeline — manifest schema, validation, sandbox, AUTHORS file, one community-authored disk accepted end-to-end

**Operating rules:** one milestone per session with automated acceptance tests; every script type-checks (`godot --headless --check-only` equivalent / strict compile) before a milestone counts; moveset frozen until M3; commit after every milestone; arcade launches with 3 disks, not 10.

**Scope management:** five major systems exist (fork/join, windows/depth, subclassing, game cubes, playground). Cut nothing, but gate hard: fork/join and Intuition-windows ship in the story; BOOPSI subclassing and playground can slip to post-launch updates.
